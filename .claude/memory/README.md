# Memory — 现实 Bug 与踩坑记录库 + 项目备忘

开发过程中每一个**现实发生的 bug**（真实报错、真实排障）修复当天必须在此录入一条。假设性、未复现的问题不录。

除 bug 外，`note-<slug>.md` 前缀存放**非 bug 的项目备忘**：设计决策定论、状态快照、用户反馈与协作约定。与仓库文档的分工：仓库文档承载正史与结论，note 承载跨会话工作约定（怎么协作、语义定论、红线）。两类都在 `_index.md` 建索引。

## 文件规范

- 一 bug 一文件：`YYYY-MM-DD-短横线标题.md`（如 `2026-09-21-glb-uv-seam-split.md`）
- 四段结构（固定）：

```markdown
# <一句话标题>

- **日期**：YYYY-MM-DD
- **现象**：报错原文 / 错误行为，能贴日志就贴日志
- **根因**：为什么
- **修复**：改了什么（文件/行为）
- **预防**：以后怎么避免再犯（可落到 CLAUDE.md 规范或代码约束的，就落）
```

## 索引

写入新条目后必须在 `_index.md` 的表格追加一行（日期 / 标题 / 一句话根因 / 关键词）。

## 使用规则

1. 修 bug 前先扫一遍 `_index.md`——同类问题不二犯；
2. bug 的"预防"段若具有普适性，同步沉淀为 `CLAUDE.md` 第 3 节的规范条款；
3. 记录面向工程读者，只写技术事实。
