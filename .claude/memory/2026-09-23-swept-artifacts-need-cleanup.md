# 产物集/命名一变，旧产物不会自己消失（被消费侧通配卷进来）

- **日期**：2026-09-23
- **现象**：两例。
  1. 交付目录 `images/` 里留着**已撤下**的图种（`hl_*.jpg`、`overview.jpg`）——本轮一次清掉
     **80 张**；页面已不引用，但目录仍带着它们分发。
  2. 单件机位由固定 `front/top/right` 改为贴合机位 `face/edge/third` 后，旧命名的
     `piece_<rank>_{front,top,right}.png` 从未清理，而交付层当时用 `piece_<rank>_*.png`
     通配取图 → **条带变成 6 张**（3 新 + 3 旧），审阅者看到的是拼接错乱的证据图。
- **根因**：交付/渲染层只负责"生成当前产物集"，**没有"删除已不在产物集里的旧文件"这一步**；
  而消费侧用通配取图，于是把陈旧文件一起卷了进来。两处叠加才形成可见故障。
- **修复**：
  1. 交付层加 `images/` **白名单清理**：只保留当前 `TRANSCODE` 输出 + 当前检出的
     `crop_*` / `locator_*`，其余删除。
  2. 视图名收口到 `lookdev_math.PIECE_VIEWS` **单一来源**；消费侧按名精确取，
     渲染端在 `--target pieces` 前清理非当前命名的残留；并加"用条带宽度反推张数"的单测
     （改回通配即失败）。
- **预防**：产物集或命名一变，必须同时回答"**旧的怎么清**"；消费侧禁止用通配去取
  "我以为只有一张"的图。与"幂等跳过致旧产物不刷新"（`2026-09-21-stale-artifacts-…`）
  是一对：那条是**不刷新**，这条是**不删除**。
- **关键词**：产物集, 清理, 白名单, 通配取图, 陈旧残留, 命名契约
