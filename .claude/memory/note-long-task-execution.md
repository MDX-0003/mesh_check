# 长任务执行约定：后台进程活不过工具调用，且幂等续跑是必需的

- **日期**：2026-09-23（两次实测）
- **事实**：用 `nohup ... &` 起的长批处理（全批渲染）**跨工具调用不可靠**：
  第一次死于命令行超限（`2026-09-23-win-argv-length-limit.md`），
  第二次整批消失、日志 0 字节——进程在工具调用结束后的某个时刻被终止。
  同时在 `--force` 全量跑到一半的期间，`data/_locator_batch.log` 始终是 0 字节（stdout 缓冲），
  **无法靠日志判断进度**。
- **约定**：
  1. 长批处理**前台分块跑**（单次调用留足超时），不要指望后台任务跨轮存活；
  2. 每次只处理一部分 key（`--keys ...`），或依赖**幂等续跑**——把"跳过判据"设计成
     收尾才写的产物（见 `2026-09-21-stale-artifacts-break-render-regression.md` 的同族第二例），
     于是重复执行同一条命令即可从断点继续；
  3. 进度**用产物计数判断**，不要读日志：`ls data/raw/*/render/<产物> | wc -l`；
  4. 重定向的日志在进程结束前可能一直为空，属正常，不是"卡住"的证据。
- **关键词**：长任务, 后台进程, 前台分块, 幂等续跑, 产物计数, stdout 缓冲
