# 既有产物被幂等跳过 → 像素回归出现假差异（基线是修复前遗留）

- **日期**：2026-09-21
- **现象**：用"仓库内既有渲染产物"当基线做像素零差异回归时，`p13@standard` 的 `wire_*.png` 报最大像素差 219、17.5% 像素不同，而同一模型的 base / highlight / 缺陷放大图**全部为 0**。第一反应是刚做的模块抽取改坏了渲染。
- **排查路径（四步，每步都在排除一种可能）**：
  1. `git stash` 把 `render_one.py` 回退到改动前重渲 → 差异**一模一样** ⇒ 与本次改动无关；
  2. 同一份代码连渲两次（`--keep` 保留两份产物）→ 两次彼此**差 0** ⇒ 线壳通道是确定性的，不是渲染抖动；
  3. 把基线与新渲并排看 → 基线是"章鱼一团**黑**"（线框密到不可读），新渲是**清晰可辨三角面**的线壳 ⇒ 基线是**降采样修复之前**（`209ccb9`/`38c797c`「网格通道降采样」）的外观；
  4. 用 `git show HEAD:meshq/blender/render_one.py` 起旧脚本渲出"重构前金样"，与重构后逐像素比 → **差 0**，确认重构无行为变更。
- **根因**：`render.py` 的幂等判定（`outputs_complete`）只要求产物"文件存在"，因此**修复类改动落地后，产物已齐的模型会被整体跳过、线壳通道从未被刷新**。PLAN-02 记录的那次"全量重渲（21 raw + 5 fixed，约 28 分钟）"按此规则跳过了部分模型——28 分钟也装不下 p13 单模型线壳通道实测所需的约 6.5 分钟（每视图约 3 分钟）。
- **影响面**：`data/report.html` 里 p13 的线框图与 PLAN-02 验收口径"线壳边线清晰、可辨三角面"**不符**；其余模型是否同样陈旧尚未逐个复核（p18 未核）。
- **预防**：
  1. 像素回归的基线必须是**同一代码路径产出**的——改渲染前先产金样，或对可疑模型用 `meshq/tools/render_regression.py --golden DIR` 指向旧代码渲出的金样；
  2. 修复类改动（渲染参数/管线）落地后，重渲要显式 `--force` 或按清单指定模型，**不要指望幂等跳过会自己刷新**；必要时补一次全量 `--force`；
  3. 现象判据：**某通道大面积差异而相邻通道为 0 时，先怀疑基线陈旧，再怀疑代码**——同一份代码的相邻通道共享场景与材质装配，真改坏了通常不会只坏一个通道。
- **关键词**：渲染回归, 幂等跳过, 陈旧产物, 像素比对, force 重渲, 金样

## 同族第二例（2026-09-23）：**完成标记用了"跑之前就写"的产物**

- **现象**：全批定位图在第 11 个模型处中断（原因见
  `2026-09-23-win-argv-length-limit.md`），修好后重跑，**前 11 个模型被跳过、剩下的继续**——
  但 p11 正好是崩掉的那个，它的定位图根本没生成，却因为"标记文件在"被判为已完成。
- **根因**：完整性判据 `target_complete` 检查的是 `locator.json`，而该文件由编排器
  **在启动 Blender 之前**写出（内容只是"要渲哪些条目"）。于是"标记存在"与"渲染完成"
  无关，崩溃在中途的模型会被永久跳过。
- **修复**：完成标记改为 `locator_marks.json`——由 Blender **收尾时**才写（内含各机位的
  投影像框）。崩塌的模型没有它，必然重渲。
- **预防**（与上文的判据问题合并成一条规则）：
  **跳过/完成判据只能指向"最后一个步骤写出"的产物。**
  拿流程中途的文件当标记，等于把"开始过"当成"做完过"；
  判据越是早写的文件，越容易把失败状态固化成"已完成"。
  自检问法：**这个文件是谁写的、写完之后还有几步？** 只要"后面还有步骤"，它就不能当标记。
