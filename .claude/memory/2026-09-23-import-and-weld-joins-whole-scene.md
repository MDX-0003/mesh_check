# `import_and_weld` 会 join 场景里全部网格 → 多对象场景被合成同一个

- **日期**：2026-09-23
- **现象**：定位图渲染时三色里只看得见一色。探针打印显示 **A 与 B 的面数相同（都 513）、
  包围盒也完全相同**——本该是"一块 2 面薄片"与"514 面的座椅"两个不同对象。
- **根因**：`bpy_geom.import_and_weld` 取的是
  `[o for o in bpy.context.scene.objects if o.type == "MESH"]`，即**场景里全部网格**，
  而不是"本次导入的"。定位图要在同一场景里放幽灵（整机）+ 组件 + 邻居三个对象，
  连调三次就把它们依次 join 成了一个（第二、三次把先前的对象一起吞并）。
- **修复**：
  1. 新增 `bpy_geom.import_glb`：记录导入前的对象名集合，只 select/join **新增**的那些；
     `render_locator_scene` 的三处导入全部改用它。
  2. 加运行期守卫：组件/邻居的面数**不多于** manifest 记录值，超出即抛错并打印三个对象的面数。
- **预防**：
  1. "合并成一个对象"的导入函数，其合并范围必须限定在**本次导入**内；跨对象渲染场景禁用。
  2. 伴生契约事实：**面数不是跨阶段恒等量**——manifest 是 trimesh 口径（weld 1e-5），
     而 Blender 导入后会过 `remove_doubles(1e-4)`，退化件会再变少（p01 的 2 面片导入后为 1 面）。
     故守卫判据只能取"不多于"（焊接只减不增，"多了"必然是又合并了）。
  3. 多对象场景一律加"对象身份"守卫，让这类静默合并变成可复现的报错。
- **关键词**：blender, import, join, import_and_weld, 多对象场景, 面数口径, 运行期守卫
