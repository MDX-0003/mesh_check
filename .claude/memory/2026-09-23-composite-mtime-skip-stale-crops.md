# 逐检出合成图的 mtime 跳过吞掉 45 张陈旧图证（改名沿用旧名的陷阱）

- **日期**：2026-09-23
- **现象**：交付页 256 张「单件外观」图证里 **45 张不是三视图条带**——尺寸五花八门
  （`15×51`、`22×27`、`1280×960`），点开看是**上一代"主场景高亮裁剪"的红色线框图**，
  与同列其它行的灰底白模条带完全不同源。视觉上像"这个组件特殊"，实际是旧产物。
- **根因**：`deliver` 的跳过判据是"目标文件不比源视图旧就跳过"。而这 45 张是
  **同一文件名的上一代语义**（旧 `crops/` 链产出的主场景裁剪，恰为 `crop_<rank>.jpg`），
  它们的 mtime 晚于 `piece_<rank>_{face,edge,third}.png`，于是**任何一次普通重跑都不会重建**
  ——`--force` 才会。`TRANSCODE` 那条链早有 `_spec_signature` 指纹防这类事，
  逐检出的合成图却漏在外面（定位图分支连 `force_transcode` 都没接）。
- **修复**（`b84e369`）：
  1. 新增 `COMPOSITE_SPEC`（条带拼法 + 视图集 + 定位图双机位/环）并入 `_spec_signature`
     指纹 → 规格一变即忽略 mtime、全量重做；
  2. 定位图分支补上 `force_transcode` 判据；
  3. 重建后 256 张 `crop_*` 全部回到 `3856×960`（三视图条带）。
- **预防**：**"文件名沿用、语义换了"比"换名字"更危险**——换名字有白名单清理兜底，
  沿用旧名则连清理都认为是同一个产物。凡是"产物形态由代码决定、不由源文件决定"的，
  跳过判据就必须挂在**代码侧指纹**上，不能只挂 mtime。同族三篇：
  `2026-09-21-stale-artifacts-break-render-regression`（不刷新）、
  `2026-09-23-swept-artifacts-need-cleanup`（不删除）、本篇（**改语义仍算旧**）。
- **关键词**：陈旧产物, 幂等跳过, mtime, 规格指纹, 图证, crop, 命名沿用
