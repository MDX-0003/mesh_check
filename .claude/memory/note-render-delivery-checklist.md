# 渲染/交付层自查清单（每次动手前扫一遍，事后补漏不划算）

- **日期**：2026-09-23
- **来历**：本仓库反复出现的故障有**高度固定的模式**，而且几乎都不是单测能拦住的。
  2026-09-23 一轮里连续冒出 3 个渲染错，**全部靠"渲一张、用眼睛看"才发现**，无一来自断言。
  故把模式收成清单，动手前对号入座。

## 一、产物与命名

1. **写入名与读取名共用同一处构造/常量**——一侧拼 `f"crop_{rank}.jpg"`、另一侧拼 glob
   模式，就是静默失效的温床（`2026-09-23-deliver-crop-glob-mismatch.md`）。
2. **产物集或命名一变，必须同时回答"旧的怎么清"**；消费侧**禁止用通配**去取"我以为只有
   一张"的图（`2026-09-23-swept-artifacts-need-cleanup.md`）。
3. 图片类验收要断言**内容非空**（占比/像素质心），不能只看"文件存在 + 方差 > 0"。

## 二、跳过与幂等

4. **跳过/完成判据只能指向"最后一个步骤写出"的产物**；问法："这个文件是谁写的、写完之后
   还有几步？"（`2026-09-21-stale-artifacts-break-render-regression.md` 的两例）。
5. 转了码/渲了图之后本地看到的旧产物可能从未被刷新——**改口径必须 `--force`**；
   交付侧的跳过方向是"dest 不旧于 src"，改模板不需 force、改图需要源更新。

## 三、跨阶段/跨引擎（都不是恒等契约）

6. **面数**：manifest（trimesh，weld 1e-5）≠ Blender 导入焊接后（1e-4），退化件会变少
   （`2026-09-23-import-and-weld-joins-whole-scene.md`）。
7. **编号**：bpy 焊接口径 vs trimesh 口径 vs 视觉岛，三套并存过（PLAN-06 §2.1）。
8. **坐标/包围盒**：`normalize()` 就地改网格，`bound_box` 要等 depsgraph 更新
   （`2026-09-23-piece-render-never-in-frame.md`）。
9. 凡"D 引擎说 A、E 引擎说 B"的字段，其失败原因往往有**多种**，不要把它写成单一物理成因
   （PLAN-06 §三"顶点重合"那次过度解读）。

## 四、渲染可读性

10. **观变换 × 自发光强度要两头试**：AgX 会去饱和、Standard 会过曝，纯色自发光从 0.4 起调
    （`2026-09-21-agx-desaturates-defect-red.md` 及其补记）。
11. **半透明与深度序**：同场有半透明对象时，"谁在前"决定颜色是否被冲淡；偏移方向用
    相机方向这类已知外向量，不要用对象自身法线（`2026-09-23-normal-offset-sinks-behind-ghost.md`）。
12. **按配置改节点树要先清空再建**，残留连线会覆盖新设定
    （`2026-09-23-world-background-not-idempotent.md`）。

## 五、流程（这条是对上面所有条的元规则）

13. **新通道/新图种首次落地，必须"先渲一个样本看一眼"再批量**；禁止直接跑全批。
    样样本要挑"最坏情况"——件数最多、组件最小、参数最极端的那个模型。
14. **批量任务的失败常常在中间**：日志可能为空（stdout 缓冲），要先看**进程在不在**与
    **产物计数**（`note-long-task-execution.md`）。
15. 页面级结论**先断言 DOM 再看截图**（`note-screenshot-verification.md`）；
    扫仓库先确认"确实扫到了全部文件"（`note-git-scan-quotepath.md`）。

## 六、跨进程传数据

16. 结构化数据**走文件**，argv 只放路径——Windows 有命令行长度上限，样本一大就中招
    （`2026-09-23-win-argv-length-limit.md`）。
- **关键词**：自查清单, 产物命名, 跳过判据, 幂等, 跨引擎契约, 观变换, 半透明, 先看不批


## 七、删除也要"删干净"（2026-09-23 补）

17. **撤掉一个数据产物时，要同时搜"谁还在引用它"**——本轮删 `crops/`、`highlight_regions`、
    `palette` 三处时各有一处静默陷阱：①`deliver` 还在读 `crops/`；②`report` 的模板里
    还有 `{{ m.image }}`/`{{ m.sheet }}`，键没了 Jinja 渲成空串 → 页面出现 **`src="data:...,"`
    的破图占位**（不报错、体积只小一点，肉眼不点开就发现不了）；③`part_features.bpy_pieces_for`
    回退读 `parts_legend.json`，删了写入方该回退会**永远静默失效**。
    做法：`grep -rn <产物名> meshq/ tests/` 全过一遍；模板类引用要**看渲染结果**而不是看有没有报错。
18. **删模块前先看它的依赖方向**：`palette.hex_to_rgb` 被 `lookdev_math.hex_to_linear` 依赖，
    而后者是**所有通道的颜色入口**——"删配色模块"实际要先搬迁它，否则整条渲染链断。
19. **删函数要扫它的 import 点，且 Blender 侧脚本必须"实跑一次"验证**：
    `d718540` 删掉 `lookdev.assign_piece_materials` 与 `lookdev_math.legend_record`，
    `render_one.py` 的 import 行没跟着改（两个名字在脚本内根本没有调用，纯死引用），
    结果**全渲染目标自那天起一律在 import 阶段崩**，而 `pytest` 全绿——因为 bpy 脚本
    不在任何单测的导入路径上。清理类提交的最小验收动作 = 跑一次最便宜的渲染目标
    （`2026-09-23-render-one-dangling-imports.md`）。

## 八、"改语义但沿用旧文件名"是最隐蔽的一类陈旧产物（2026-09-23 补）

20. 跳过判据若只看 mtime，则**上一代同名产物只要比源文件新，就永远不被重建**——
    实测 256 张 `crop_<rank>.jpg` 里 45 张仍是旧"主场景裁剪"语义。凡是"产物形态由代码
    决定、不由源文件决定"的图，跳过判据必须挂在**代码侧规格指纹**上
    （`deliver._spec_signature` 已把转码规格与逐检出合成图造型一并纳入）；
    新增图种时问一句"它的样子由哪几行代码决定？"（`2026-09-23-composite-mtime-skip-stale-crops.md`）。

## 九、交付物里不许有本机信息（2026-09-23 补）

21. **内部缓存文件会随交付被复制出去**：`pieces/manifest.json` 曾用 `str(path.resolve())`
    写死开发机绝对路径，20 份随快照入库。交付前扫本机路径的范围要覆盖**整个快照目录**
    （含 `pieces/`、`data/` 附录里的每个 JSON），不能只扫页面
    （`2026-09-23-manifest-absolute-paths-in-snapshot.md`）。
- **关键词**：自查清单, 产物命名, 跳过判据, 幂等, 跨引擎契约, 观变换, 半透明, 先看不批,
  悬空导入, 规格指纹, 绝对路径
