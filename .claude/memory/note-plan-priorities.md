# 计划重心：判别优先，方法论可降级

- **日期**：2026-09-21（用户纠正过一次）
- **要点**：
  1. **判据/规则设计本身才是交付物核心，验证方法只是支撑**——验证轨道可保留但必须降级为"可选/暂不启用"，不能占主体篇幅、不能当门槛卡主线（用户原话背景：曾把"重生成稳定性实验"写成 PLAN-03 必备门槛，被纠正"我更关心高置信碎片、高置信部件的判别和处理，这是这份作业的核心"）。
  2. **"特征提取器" ≠ "判别器"**：特征提取是把对象变成一行可比较数字的输入层；判别是"用这些数字怎么分档、冲突怎么消解、每档怎么处理、理由怎么输出"的规则层。两者分章写。
  3. 用户认可"阈值留给数据、结构现在定死"：先定真值表/优先级/处理策略/解释格式，阈值等新样本到货再标定。
- **协作方式**：写计划先问"这份交付的核心是什么"，章节权重压在核心上，方法论写短可降级；用户对内容权重判断很准且会直接指出错配——被纠正后应当场重构文档，不要小修小补。
