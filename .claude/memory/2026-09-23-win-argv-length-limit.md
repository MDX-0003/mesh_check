# Windows 命令行长度上限：整批在第 11 个模型处静默中断

- **日期**：2026-09-23
- **现象**：全批定位图渲染跑到第 11 个模型就没了——进程消失、日志 **0 字节**，
  而单独重跑 p11 一切正常。日志（缓冲刷出后）里才看到
  `FileNotFoundError: [WinError 206] 文件名或扩展名太长`。
- **根因**：定位图清单（每条含 GLB 绝对路径、方向向量、面数等）整包 JSON 塞进命令行
  传给 Blender；p11 有 **94 条**检出，超过 Windows 的命令行长度上限。
- **修复**：清单只传**文件路径**（`locator_items_path`），Blender 侧 `json.load` 读文件。
- **预防**：
  1. 跨进程传递结构化数据一律**走文件、argv 只放路径**；批量任务里"某个样本特别大"就会触发。
  2. 失败点在批处理中段、且重定向后日志可能为空（stdout 缓冲），排查时要先看**进程还在不在**
     与**产物计数**，而不是只看日志末尾。
- **关键词**：windows, argv, 命令行长度, WinError 206, 跨进程, 批处理
